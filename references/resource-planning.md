# 资源规划：从盘点表到可审阅的 plan

> 一句话结论：**工具只盘点、只出候选，从不分配。**
> 一条地址要变成可执行的事，必须先出现在 `plan.resources` 里，且 `source` 是
> `user` 或 `io-table`。`source=suggested` 会让 `plan-lint` 直接失败。

---

## 1. 为什么不能自动分配

2026-11 之前的版本把这条写成「不自行分配 I/O、寄存器、定时器、计数器、预置值
或联锁关系」。它针对的是**模型静默猜地址并写死**，不是反对做规划。

猜错的代价：

| 猜错的点 | 后果 |
|---|---|
| `I`/`O` | 实际接的是安全门或液压阀，软件里看不出来 |
| `R81~R100` | 由系统参数 3401~3420 单向写入，阶梯写它无效 |
| `R640` 以上 | 部分是 CNC 接口区，手册按版本分成只读/可写 |
| `C` | 直接给 CNC 下命令，写错就是撞机级别的动作 |
| `S` | 只读状态，写成线圈会被 `lint` 抓，但已经生成的交付要返工 |
| 看似空闲的 `A`/`R` | 可能被 HMI 画面、宏程序、未打开的子程序占用 |

`lint` 能查重复线圈、越界、`S` 当线圈；查不出「这个点其实接了安全门」。
语法通过 ≠ 点位正确，所以把判断权留给人。

---

## 2. 三层流程

```
resource-report  →  plan.resources  →  plan-lint  →  build / patch
   （扫描）           （人确认）        （机器校验）
```

### 2.1 `resource-report`：看清楚现状

```bash
python scripts/run_syntec_lad.py resources cnc.lad --io 点位表.csv
python scripts/run_syntec_lad.py resources cnc.lad --format csv --output 现状.csv
```

输出内容：

- 每个族（`I/O/A/C/S/TM/CT/R`）已用地址、读次数、写次数、所属程序、网络号；
- 该地址现有的 type-4 注释（符号 + 短说明）；
- 空闲区间候选（`R` 默认只扫到 1023，用 `--r-max` 可改）；
- 只读区被写的告警；
- 给 IO 点表时，双向差集：梯图有表里没有 / 表里有梯图没有。

**空闲候选不是分配结果。** 报告里会打印这句话，不要省。

### 2.2 `plan.resources`：人确认后的登记表

字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `addr` | 是 | `I0` / `R200.03` / `TM12` 等 |
| `source` | 是 | `io-table` / `user` / `scan` / `suggested` |
| `symbol` | 建议 | 图上用的短名，如 `润滑泵` |
| `purpose` | 建议 | 什么时候驱动、什么条件下断开 |
| `permission` | 可选 | `read` / `write` / `readwrite` |
| `retain` | 可选 | 只有确认过是掉电保持区才写 `true` |
| `owner` | 建议 | 归哪个程序/功能所有 |
| `note` | 可选 | 现场差异、选配说明 |

`source` 的判定标准：

- `io-table`：客户 IO 点表里有这一行，地址和描述都能对上；
- `user`：客户口头/书面确认；
- `scan`：从 `resource-report` 抄来的**既有**地址，不是新分配的；
- `suggested`：模型建议，**永远不能进 build**。

### 2.3 `plan-lint`：机器能查的部分

| 规则 | 级别 | 含义 |
|---|---|---|
| `resource_unverified` | error | 还有 `source=suggested` |
| `resource_source_invalid` | error | `source` 不在枚举里 |
| `resource_duplicate` | error | 同一地址登记两次 |
| `resource_readonly_write` | error | 写了只读区 |
| `r_bit_access_invalid` | error | 写了 `R640+` 的位，如 `R700.0` |
| `r_retain_mismatch` | error / warning | `retain` 标记与 R 分区不一致 |
| `r_system_write` | warning | 写逐条定义的系统接口区，且不在已知可写例外内 |
| `r_conditional_zone` | warning | 用条件占用区但没在 note 写明 Pr 条件 |
| `resource_missing` | warning | 用了 `I/O/C/S` 或 `R0~R255` 却没登记 |
| `resource_unused` | info | 登记了但没用到 |

`resources` 段缺失时保持旧行为（不报错），但**新建流程必须提供**。

## 3. 各族规划规则

### 3.1 `I` / `O`

- 一点一义，不要同一物理点在不同程序里代表不同东西。
- 需要重复使用时，映射到 `A300+n` / `A400+n` 镜像位，梯图里只引用镜像位。
- 输出点不要直接被多个网络线圈驱动；`lint` 的 `duplicate_coil` 会抓。
- 地址必须来自 IO 点表。表里没有就先问，不要挑一个空号。

### 3.2 `A` 辅助位

- `A200~A299` 是 PLC 功能性辅助接点，内部怎么切**没有标准**。
- 唯一规则：同一功能连续放，不要和其他功能交错。润滑放 `A200~A219` 就一直放这段。
- 预留增长空间，不要一个功能用完 20 个位后紧贴下一个功能。

### 3.3 `R` 数值寄存器

完整分区、权限、保持、位存取和 `@` 映射见 `register-map.md`；
机器可读版本在 `syntec_lad/data/register-zones.json`。

先按数据性质选区：

| 想存什么 | 首选 | 说明 |
|---|---|---|
| 中间标志 | `A0~A511` | 不要用 `Rxx.y` 代替 A |
| 操作员参数 | `R81~R100` | 对应 Pr3401~3420，阶梯只读 |
| 掉电保持数值 | `R193~R255`、`R6000~R7999`、`R10000~R10999` | 避开刀号段和被应用占用的区 |
| 临时数值 | `R50~R80`、`R256~R511`、`R1033~R2049`、`R3101~R4095` | 掉电不保持 |
| 条件占用区 | `R2050~R2090`（Pr3810）、`R2100~R3100`（Pr3228） | note 必须写明条件 |
| 大块用户区 | `R20000~R65535` | 宏只读，阶梯可读写 |

规则：

- 写 `R` 前先 `lookup R2050` 看分区，不要只看地址索引的描述；
- 需要操作员改的参数，用 `R81~R100`，不要写死在程序里；
- 需要跨断电记住的数值，用保持区；不要用 `R50~R80`；
- 不要因为「看着空」就复用 `R103~R192`，那是刀号区；
- `R640` 以上不能位存取；
- `R512~R1023` 是逐条权限，不能整片判只读。

### 3.4 `C` / `S`

- `C` 是给 CNC 的命令位，一个位对应一个明确动作，必须有注释说明触发条件。
- `S` 是 CNC 只读状态，只能当触点，不能线圈。
- 用之前先 `lookup` 查语义，不要凭编号猜。

### 3.5 `TM` / `CT`

- 预置值用 `R` 或常数，不要在多处写不同的魔数。
- 同一个定时器不要在不同程序里用不同时基。

## 4. 新建与修改的差别

| | 新建 | 修改 |
|---|---|---|
| 起点 | 空资源表 | `resource-report` 扫出现状 |
| 审核重点 | 每个点是否来自 IO 点表/客户确认 | 新增点是否与既有引用冲突 |
| 基线保护 | 不适用 | change 文档钉住原文件 hash |
| 既有地址 | 不适用 | 默认锁定，不因「看着空」复用 |

修改流程：

1. `resource-report` 出基线（连同 sha256 一起记录）；
2. 在基线之上标出新增/复用；
3. change 文档的 hash 必须匹配基线，否则先重新扫描；
4. change 文档同样带 `resources`，只登记本次新增的地址；
5. `plan-lint` 会识别 change 文档，按 `operations[].networks` 统计地址；
6. `patch` 在应用前跑同一道门禁，有 `suggested` 或写只读区就拒绝。

### 4.1 点表地址写法必须归一

客户点表常写 `I000`，梯图内部是 `I0`。`resources --io` 现在两侧都
规范化后再比较，所以 `I000` 和 `I0` 视为同一点。如果看到整批误报，
先确认是不是版本太旧。

## 5. 人工审查清单

审 `plan.resources` 时逐条问：

- [ ] 这个 `I`/`O` 在 IO 点表里能查到吗？描述对得上吗？
- [ ] 这个 `R` 的权限允许阶梯写吗？
- [ ] 需要掉电保持的数值，放的是保持区吗？
- [ ] 条件占用区（R2050~R2090、R2100~R3100）的 Pr 条件确认了吗？
- [ ] 写的是 `R640+` 的位吗？（不允许）
- [ ] `A` 位是否按功能连续、留了余量？
- [ ] 旧程序里「看着空」的地址，是否确认过 HMI/宏没在用？
- [ ] 每个 `C` 位的触发条件写清楚了吗？
- [ ] 有没有 `source=suggested` 混进来？

---

## 6. 反模式

- 把 `resource-report` 的空闲候选直接抄进 plan，`source` 写 `scan`。
  它不是「既有地址」，是候选，必须走确认。
- 为了让 `plan-lint` 通过，把 `suggested` 批量改成 `user`。这等于自己骗自己。
- 一个 `I` 点在五个程序里各写一次，不做镜像。
- 用 `R103~R192` 存产量，和刀号数据打架。
- 新建时先画图后补资源表。顺序反了，地址就会跟着图走，而不是跟着现场走。
