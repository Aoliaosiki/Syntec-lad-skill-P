# 注释分级：写什么、写多长、什么时候可以不写

> 一句话结论：接口类元件必须有短注释，程序头必须有说明，内部中间位按需。
> 不是为了凑覆盖率，而是让半年后的人能查线。

---

## 1. 三级定义

| 级别 | 对象 | 强制程度 | 形式 |
|---|---|---|---|
| L1 | 对外接口：I/O/C/S、R0~R255、R8000~R8255 | 必须 | type-4 短注释（挂在地址上） |
| L2 | 每个程序、每个独立功能段 | 必须 | type-1（主程序）/ type-3（子程序）行注释 |
| L3 | 互锁组、状态机、异常恢复、易误解逻辑 | 按需 | type-1/3 长注释或段内分节 |

L1 是硬要求，因为它决定「这根线是干什么的」。
L3 不强制，写多了反而埋掉重点。

---

## 2. L1：接口类必须写短注释

哪些地址算 L1：

- 所有 I、O：实体点位，现场查线第一眼要看；
- 所有 C：给 CNC 的命令位，写错动作就错；
- 所有 S：CNC 只读状态，读者要知道这个状态代表什么；
- R0~R255：HMI、参数、保持区，跨程序或跨设备可读；
- R8000~R8255：宏程序可读写、阶梯只读，语义必须和宏一致；R8256 以上系统区不要占用。

短注释写法（type-4，`set_comment`）：

```
地址 \t 短名 \t 补充说明
I000 \t 启动按钮 \t 操作面板绿色按钮，常开
R200 \t 润滑累计次数 \t 掉电保持，满 500 次提示保养
```

- 短名控制在 6~10 个字，能贴在图上；
- 补充说明写「谁的信号、什么条件、掉不掉电」，不要复述指令；
- 写完过 `zhconv` 转繁体，再写入。

长度判断：

| 情况 | 写法 |
|---|---|
| 一个按钮、一个阀 | 短名即可 |
| 有极性、有边沿要求 | 短名加一句说明 |
| 和 HMI/宏共享 | 短名加共享方和读写方向 |
| 有选配差异 | 短名加适用机型 |

---

## 3. L2：程序头必须有

每个程序（MAIN 和每个子程序）开头至少三行：

```
程序名 / 功能标题
输入输出：用到的 I/O、C、S
参数：用到的 R81~R100、R193~R255
```

多段功能可以在头部列目录，段内再用 type-1 分节：

```
【润滑】A200~A219
【刀库】A220~A259
【报警】R40~R49
```

程序头是 `comment_coverage` 判 L2 的唯一客观依据：
程序记录范围内存在任意 type-1 或 type-3 注释即视为有头：
编译器给 MAIN 写 ct=1，给子程序写 ct=3，两者都占一行。

---

## 4. L3：什么时候值得写长注释

只有这四类值得：

1. 互锁组：三个以上条件互相牵制，光看图要来回翻；
2. 状态机：有明确 step 变量和转移条件；
3. 异常恢复：断电/急停/报警后的复位顺序；
4. 反直觉逻辑：为兼容老机型故意保留的怪写法。

不值得写的：

- 每个 A 中间位都写一句「XX 中间继电器」；
- 把指令翻译一遍：「I0 接通则 O0 输出」；
- 显而易见的分段：「这一段是润滑」单独占一行却没内容。

---

## 5. 工具怎么判

```bash
python scripts/run_syntec_lad.py comments cnc.lad
python scripts/run_syntec_lad.py comments cnc.lad --json --output 覆盖率.json
```

输出：

- L1 覆盖率（`l1_commented / l1_total`）；
- L2 有头注释的程序数；
- L3 长注释条数（只统计，不强制）；
- 缺失清单，按级别分组，带程序/网络定位。

`lint` 只输出一条汇总 info，不阻断：

```
[INFO] comment_coverage: 12 个接口类元件没有注释
```

这样既看得见，又不会把「还没补注释」变成交付失败。

---

## 6. 豁免

确实不需要注释的情况（临时调试位、明确的一次性地址），
在 plan 的 `resources.note` 里写理由，而不是在代码里加空注释占位。

豁免不等于隐藏：`comments` 报告仍会列出它，审阅时能看到。

---

## 7. 编码与简繁

- .lad 注释固定 cp950（Big5 繁体）；
- 简体字写进去不报错，编辑器显示问号或整段被吞；
- 写之前先 `zhconv`，`lint` 会报 `simplified_comment`。

---

## 8. 反模式

- 给每个内部 A 位都写注释，注释比逻辑还长；
- 注释复述指令，不写信号来源和条件；
- 程序头只写「主程序」三个字；
- 用注释解释一个本可以拆开的复杂网络，而不是拆开它；
- 为了把覆盖率刷到 100%，给未使用的地址也补注释。
